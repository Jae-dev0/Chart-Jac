The Jac-Chart CLI is a single `jac-chart` binary. Install it with one command.

On macOS and Linux:

```bash
curl -fsSL https://jac-chart.app/cli/install.sh | sh
```

On Windows, in PowerShell:

```powershell
irm https://jac-chart.app/cli/install.ps1 | iex
```

The script downloads the build for your system from the [GitHub release](https://github.com/Jae-dev0/Jac-Chart/releases), checks it against the release's SHA-256 checksums, and only then replaces any existing `jac-chart`. Nothing else is needed, not even Node.js.

- On macOS and Linux it installs to `~/.local/bin/jac-chart`. If that directory is not on your `PATH`, the script prints the command that adds it for your shell (bash, zsh, fish or another).
- On Windows it installs to `%LOCALAPPDATA%\Programs\jac-chart\jac-chart.exe` and adds that directory to your user `PATH`. Open a new terminal afterwards.

Then [sign in](/cli/sign-in) and run `jac-chart` on its own to see your account, your open tasks and the main commands.

<Tip>
Both scripts are plain text. Read them before running them: [install.sh](https://github.com/Jae-dev0/Jac-Chart/blob/main/apps/site/public/cli/install.sh) and [install.ps1](https://github.com/Jae-dev0/Jac-Chart/blob/main/apps/site/public/cli/install.ps1), or print one with `curl -fsSL https://jac-chart.app/cli/install.sh | less`.
</Tip>

## Install with Homebrew

On macOS and Linux with [Homebrew](https://brew.sh):

```bash
brew install Jae-dev0/tap/jac-chart
```

Update it with `brew upgrade jac-chart` and remove it with `brew uninstall jac-chart`. Homebrew installs the same binary as the install script, from the CLI release, and checks it against the release checksums.

## Install with npm

With Node.js 20 or newer, you can install the same CLI from npm instead:

```bash
npm install -g @jac-chart/cli
```

Update it with `npm install -g @jac-chart/cli@latest` and remove it with `npm uninstall -g @jac-chart/cli`. Every install method shares your logins and settings. Keep one of them per machine: with more than one installed, whichever comes first on your `PATH` runs, and the install script warns about the other copy.

## Install options

Set these environment variables to change what the script does:

| Variable | What it does |
| --- | --- |
| `JAC_CHART_VERSION` | Install this version, such as `0.1.0` or `cli-v0.1.0`, instead of the latest release |
| `JAC_CHART_INSTALL_DIR` | Install into this directory instead of the default |
| `JAC_CHART_DOWNLOAD_URL` | Download from a mirror instead of GitHub. Requires `JAC_CHART_VERSION` |

Pin a version, or install into another directory:

```bash
curl -fsSL https://jac-chart.app/cli/install.sh | JAC_CHART_VERSION=0.1.0 sh
curl -fsSL https://jac-chart.app/cli/install.sh | JAC_CHART_INSTALL_DIR="$HOME/bin" sh
```

```powershell
$env:JAC_CHART_VERSION = "0.1.0"; irm https://jac-chart.app/cli/install.ps1 | iex
$env:JAC_CHART_INSTALL_DIR = "C:\tools\jac-chart"; irm https://jac-chart.app/cli/install.ps1 | iex
```

Without `JAC_CHART_VERSION`, the script asks the GitHub API for the newest CLI release (tags that start with `cli-v`). GitHub allows 60 of these lookups per hour from one IP address without a token, so set `JAC_CHART_VERSION` in CI.

## Mirrors and offline machines

`JAC_CHART_DOWNLOAD_URL` replaces `https://github.com/Jae-dev0/Jac-Chart/releases/download`. The script then downloads `<url>/cli-v<version>/SHA256SUMS` and `<url>/cli-v<version>/<file>`, so a mirror keeps the same layout as the GitHub release. It makes no call to the GitHub API, which is why `JAC_CHART_VERSION` is required.

```bash
curl -fsSL https://jac-chart.app/cli/install.sh | JAC_CHART_DOWNLOAD_URL=https://mirror.example.com/jac-chart JAC_CHART_VERSION=0.1.0 sh
```

For a machine without internet access, copy `install.sh` (or `install.ps1`), `SHA256SUMS` and the file for that machine from the release into a `cli-v<version>` folder, then point `JAC_CHART_DOWNLOAD_URL` at the folder that contains it. `install.sh` accepts a `file://` URL when it downloads with curl, and `install.ps1` accepts a local or network path:

```bash
JAC_CHART_DOWNLOAD_URL=file:///opt/jac-chart-mirror JAC_CHART_VERSION=0.1.0 sh install.sh
```

```powershell
$env:JAC_CHART_DOWNLOAD_URL = "\\fileserver\jac-chart"; $env:JAC_CHART_VERSION = "0.1.0"; Get-Content -Raw .\install.ps1 | iex
```

## Supported systems

| System | Builds |
| --- | --- |
| macOS | Apple silicon and Intel. On Apple silicon the script installs the native build even when the terminal runs under Rosetta |
| Linux | x64 and arm64, for glibc distributions and for musl distributions such as Alpine |
| Windows | x64. Windows 11 on Arm runs the x64 build through emulation |

The x64 builds are baseline builds, so they also run on older processors without AVX2. On Alpine and other musl distributions, the CLI needs the C++ runtime library. The script warns when it is missing:

```bash
apk add libstdc++
```

Prefer the install script to downloading a binary from the release page with a browser. The macOS builds are signed ad hoc but not notarized, so Gatekeeper can block a copy that a browser downloaded. Files downloaded with `curl`, as the script does, are not affected.

## Update

Run the install command again. It replaces `jac-chart` with the latest release, or with the version in `JAC_CHART_VERSION`, and keeps your logins and settings. Check the result with `jac-chart --version`.

If the script warns that another `jac-chart` comes first on your `PATH`, for example an older community CLI, it shows both paths. Remove the other one, or move the install directory earlier in your `PATH`.

## Uninstall

Delete the binary. To also remove your stored logins and settings, delete the config directory:

```bash
rm ~/.local/bin/jac-chart
rm -rf ~/.config/jac-chart
```

```powershell
Remove-Item "$env:LOCALAPPDATA\Programs\jac-chart" -Recurse
Remove-Item "$HOME\.config\jac-chart" -Recurse
```

On Windows, also remove `%LOCALAPPDATA%\Programs\jac-chart` from your user `PATH` (search the Start menu for "Edit environment variables for your account"). If you set `JAC_CHART_INSTALL_DIR`, `XDG_CONFIG_HOME` or `JAC_CHART_CONFIG`, delete those locations instead.
