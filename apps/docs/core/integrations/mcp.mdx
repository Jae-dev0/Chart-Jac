title: Jac-Chart MCP Server
description: Connect Jac-Chart to MCP clients like Cursor and Claude Desktop using the official Jac-Chart MCP server.
---

Jac-Chart supports the Model Context Protocol (MCP) in two ways:

1. **Built-in HTTP endpoint**: every Jac-Chart instance exposes `/api/mcp` out of the box. No extra setup, no extra process.
2. **Stdio package** ([`@jac-chart/mcp`](https://www.npmjs.com/package/@jac-chart/mcp)): the official Jac-Chart MCP package on npm, a local stdio server for clients that prefer stdio transport.

Both offer the same tools for managing workspaces, projects, tasks, comments, and labels.

To work with Jac-Chart from a terminal or a shell script instead, use the [Jac-Chart CLI](/cli).

## Built-in HTTP endpoint

Every Jac-Chart API instance ships with a Streamable HTTP MCP endpoint. This is the recommended approach for self-hosted deployments.

Point your MCP client at:

```
https://your-jac-chart-instance.com/api/mcp
```

With an OAuth-capable client, you will be redirected to Jac-Chart to sign in and explicitly approve the MCP client. After approval, all MCP tools run as your authenticated user.

The endpoint implements OAuth 2.1 with PKCE for authentication. Discovery metadata is available at:

- `/.well-known/oauth-protected-resource/api/mcp`
- `/.well-known/oauth-authorization-server/api`

The endpoint serves both MCP protocol eras without server-side sessions. Modern
`2026-07-28` requests are self-contained; 2025-era clients still send
`initialize`, but Jac-Chart does not issue a session ID. See [MCP protocol
reference](/core/integrations/mcp-stateless) for transport behavior, proxy
requirements, and request limits.

## Stdio package

The `@jac-chart/mcp` package runs a local stdio MCP server and authenticates with Jac-Chart using device authorization. Use this when your MCP client requires stdio transport.

### Prerequisites

- Node.js 24 or newer
- A running Jac-Chart API
- Access to the Jac-Chart web app to approve device login

By default, self-hosted Jac-Chart allows both `jac-chart-cli` and `jac-chart-mcp` as device auth client IDs.

### Install and register

Use the recommended interactive installer:

```bash
npx -y @jac-chart/mcp
```

The installer lets you choose where to register the server configuration:

- Cursor (user-wide)
- Cursor (project-level)
- Claude Desktop
- Custom JSON config path

You can also run the explicit install command:

```bash
npx -y @jac-chart/mcp install --target cursor-user -y
```

Use `--help` to see all available targets and flags:

```bash
npx -y @jac-chart/mcp install --help
```

### Point to a self-hosted instance

When generating config, pass your Jac-Chart base URL:

```bash
npx -y @jac-chart/mcp install --target cursor-user -y --api-url https://jac-chart.example.com
```

Or set it via environment variable:

| Variable | Description |
| --- | --- |
| `JAC_CHART_API_URL` | Jac-Chart API base URL. Default: `http://localhost:1337`. A trailing `/api` is accepted and normalized. |
| `JAC_CHART_MCP_CLIENT_ID` | Device auth client ID. Default: `jac-chart-mcp`. |

If you override `JAC_CHART_MCP_CLIENT_ID`, make sure it is included in [`DEVICE_AUTH_CLIENT_IDS`](/core/installation/environment-variables).

### Authentication flow

On the first tool call that needs Jac-Chart access, the MCP server:

1. Requests a device code from Jac-Chart
2. Prints a verification URL and user code
3. Opens the browser when possible
4. Polls until you approve sign-in
5. Stores credentials in `$XDG_CONFIG_HOME/jac-chart-mcp/credentials.json`, or `~/.config/jac-chart-mcp/credentials.json` when `XDG_CONFIG_HOME` is unset

## Available tools

Both the HTTP endpoint and stdio package expose the same tools:

- Session: `whoami`, `list_workspaces`, `list_workspace_members`, `list_notifications`
- Search: `search`
- Projects: `list_projects`, `get_project`, `create_project`, `update_project`, `list_project_columns`
- Tasks: `list_tasks`, `get_task`, `get_task_by_ticket_id`, `create_task`, `duplicate_task`, `update_task`, `delete_task`, `move_task`, `update_task_status`, `update_task_assignee`, `update_task_due_date`, `list_task_activity`
- Time entries: `list_task_time_entries`, `get_time_entry`, `create_time_entry`, `update_time_entry`
- Comments: `list_task_comments`, `create_task_comment`, `update_task_comment`, `delete_task_comment`
- Labels: `list_workspace_labels`, `create_label`, `attach_label_to_task`, `detach_label_from_task`, `delete_label`
- Task relations: `create_task_relation`, `get_task_relations`, `delete_task_relation`

Use `get_task_by_ticket_id` with a key such as `KAN-12` to fetch one task directly. If the same key identifies multiple accessible tasks, pass `workspaceId` or `projectId` to select one.

`list_project_columns` is worth calling first when setting a status: the column
slugs it returns are exactly the values `create_task` and `update_task_status`
accept. Likewise `list_workspace_members` resolves the user IDs the assignee
tools expect. Time entries have no delete endpoint on the API, so there is no
`delete_time_entry` tool.

## Debugging

To run the stdio server directly:

```bash
npx -y @jac-chart/mcp serve
```

When running from source in this monorepo:

```bash
pnpm --filter @jac-chart/mcp run build
pnpm --filter @jac-chart/mcp run start
```
